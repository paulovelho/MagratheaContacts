Placeholders

Write your template's subject and HTML content using {{ '{{placeholder}}' }} variables — for example {{ '{{first_name}}' }} or {{ '{{order_id}}' }}. Placeholder names may contain letters, numbers and underscores.

The variable map is extracted automatically when you save: every placeholder found in the subject or content becomes a variable, and you can give each one a default value. When an e-mail is sent without a value for a variable, the default is used; with no default, it renders as an empty string (the e-mail still goes out).

Source and global templates

A template assigned to a source can only be used by that source's API keys. A global template (no source) can be used by any key. When a source template and a global one share the same name, the source template wins. Only active templates can be used for sending.

Sending with a template

Integrations send templated e-mail through the same POST /add and POST /send endpoints, passing template (name) or template_id, plus a vars object with the placeholder values: 

{{ '{' }}
	"key": "your-api-key",
	"to": "someone@example.com",
	"template": "welcome",
	"vars": {{ '{' }} "first_name": "Arthur" {{ '}' }}
{{ '}' }}

/add queues a mail promise, rendered later by the promise processor (or immediately with "process": 1). /send renders and sends right away. A subject or message sent in the request overrides the template's.

E-mail clients render HTML much more conservatively than browsers. The rules that matter:

  • Use table-based layouts with a max width of ~600px. Flexbox and grid are not supported.
  • All CSS must be inline (style="..."). No JavaScript, no external stylesheets.
  • Stick to web-safe fonts (Arial, Helvetica, Georgia, Times New Roman).

Images must be publicly hosted

The template is sent as an e-mail: the recipient's mail client fetches every image from the internet. Image URLs must be absolute, public HTTPS links (e.g. https://your-cdn.com/logo.png). Local paths, relative URLs and private/intranet hosts will show up as broken images. Base64-embedded images are also blocked by many clients — host the file and link to it instead. Always set width, height and alt on every image.

Avoid embedded SVG

Inline <svg> markup is not reliably supported in e-mail: Gmail and Outlook strip it out, and most clients also refuse .svg files referenced by <img>. Export your vector art as PNG (or JPG), host it publicly, and reference it like any other image.
